# ASR and diarization survey, 2026-10-17 (annex to asr-diarization-2026-10.md)

Web survey (model cards, papers, sherpa-onnx docs, leaderboards) for an on-device zh-TW + en meeting app:
CPU only, Oppo Reno7 (Dimensity 900: 2×A78 @ 2.4 GHz + 6×A55, 8 GB), app licensed GPL-3.0. Every number
links to its source; "est." marks an estimate, "unknown" what could not be verified. The benchmark section
of the main report measures the top candidates on our own data; numbers here are the publishers'.

## Key findings

1. **The shipped diarizer runs a smaller speaker cache than every NVIDIA preset.** The
   [Nemotron-3-Diarization card](https://huggingface.co/nvidia/Nemotron-3-Diarization) uses `SPKCACHE_LEN`
   264 in all presets; the app uses 128 (a speed choice, `engine.h`). The model handles up to 8 speakers.
   At 1.04 s latency the card reports DER AliMeeting-far 10.80, AMI-SDM 12.80, AMI-MHM 9.48 — collar 0 and
   forced-alignment references, so not comparable with our md-eval-style references (see main report).
2. **X-ASR's own weights give a cheap second pass.** The model is unified offline/streaming; its
   [card](https://huggingface.co/GilgameshWind/X-ASR-zh-en/raw/main/README.md) reports WenetSpeech meeting
   9.31 at 480 ms streaming vs 7.20 offline (−23 % relative), WS-net 7.38 → 5.96, 1920 ms chunks 8.03.
   sherpa-onnx publishes int8 exports of the 160/480/960/1920 ms streaming variants and of the offline
   model (`sherpa-onnx-x-asr-zipformer-transducer-zh-en-int8-2026-06-03`).
3. **Best published zh-TW / code-switch numbers: the Qwen3-ASR family.** TEA-ASR-1-mini (Qwen3-ASR-0.6B +
   LoRA, 780M) CV19 zh-TW 5.14, ASCEND 12.49, NTUML2021 7.37 ([card](https://huggingface.co/JacobLinCool/TEA-ASR-1-mini));
   Breeze-ASR-25 8.03 / 17.53 / 7.50 on the same sets. sherpa-onnx runs Qwen3-ASR-0.6B int8 on Android.
4. **No 2025–26 release is a better streaming zh+en first pass than X-ASR at a 2×A78 budget.**

Compute estimates for 2×A78 (survey agent): SenseVoice int8 0.065 RTF on 2×A76 (RK3588) is the only real ARM
anchor; non-autoregressive encoders scaled by parameters; autoregressive decoders (Qwen3-ASR, Fun-ASR-Nano,
FireRed-AED) add one ~0.6B int8 forward per token, memory-bandwidth bound and competing with Gemma E2B.
The main report replaces these with measured host core-RTF and a Note10+ probe.

## Two-pass evidence

- WeNet U2++ attention rescoring, AISHELL-1 streaming chunk 16: 5.81 → 5.05 (−13 %) ([WeNet](https://github.com/wenet-e2e/wenet/blob/main/examples/aishell/s0/README.md)).
- Google RNN-T + LAS rescoring: −17 to −22 % relative ([arXiv 1908.10992](https://arxiv.org/abs/1908.10992)).
- X-ASR offline vs 480 ms streaming, same weights: −19 % (WS-net), −23 % (WS-meeting) ([card](https://huggingface.co/GilgameshWind/X-ASR-zh-en/raw/main/README.md)).
- sherpa-onnx ships two-pass Android APKs that re-decode each endpointed segment with an offline model
  ([list](https://k2-fsa.github.io/sherpa/onnx/android/apk-2pass.html)).
- No published Mandarin number for a SenseVoice / Breeze / Qwen second pass over a streaming first pass.

## Caveats

- Several cards publish numbers only as images (SenseVoice per-set, Dolphin, GLM-ASR, diart).
- sherpa "desktop" RTFs come from unnamed hosts; no ARM RTF was found for Qwen3-ASR, Fun-ASR-Nano,
  FireRedASR2, Nemotron ASR or Gemma-4 audio.
- Licences: FunASR model licence signals conflict (HF tags Apache, repo MODEL_LICENSE custom); OpenMDW-1.1
  and NVIDIA OML vs GPL-3.0 are unresolved — this also concerns the shipped Nemotron-3-Diarization; the
  CAM++ ModelScope weights' licence was not verified.
- TEA-ASR numbers are self-reported, single run, script-folded.
